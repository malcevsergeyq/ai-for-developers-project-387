pull request → ревью → merge. Источник — раздел «Открытые вопросы» и «Следующие шаги»

меньше связей у кода, тем безопаснее отдать его агенту без построчного чтения.

## Подробности по задачам

### 1. Демо-данные за флагом — закрыта 2026-08-30

Два типа встреч засеваются в `server/index.js` при пустом хранилище. Решение модуля 1 было
осознанным: иначе проверяющий открывает пустую страницу и до пути записи не доходит. Для
продакшена поведение нежелательно — вынес за флаг окружения `SEED_DEMO`. Засев включён
по умолчанию (локальный `npm start` и контейнер проверки Hexlet, на который `render.yaml`
не распространяется), продакшен на Render подавляет его `SEED_DEMO=false` в `render.yaml`.

### 2. Changelog отменённого скоупа

Открытый release-PR собрал changelog по всей истории репозитория модуля 1, включая фичи,
которых в коде уже нет: расписания доступности и правило 12. При переносе истории в этот
репозиторий проблема переехала вместе с ней.

### 3. Холодный старт Render

Free-план усыпляет сервис после 15 минут без запросов. Первый запрос после сна ждёт около
минуты, пока поднимется контейнер. Само по себе это не баг приложения, но регулярная
проверка производительности будет ловить именно этот случай — и отчёт должен быть читаемым
с учётом этого.

### 4. Postgres и pg-ветка

Приложение работает на in-memory хранилище; Postgres-реализация за тем же интерфейсом
**ни разу не исполнялась**. Если задать `DATABASE_URL` на деплое, код уйдёт в непроверенную
ветку и упадёт уже в проде. Не проверены: exclusion-ограничение `bookings_no_overlap`,
`gen_random_uuid()`, приведение `id::text`, перевод SQLSTATE `23P01` в 409.

### 5. Защита `/admin/*`

Административные роуты открыты. Авторизация была вынесена за скоуп техзаданием модуля 1 и
осталась долгом. Задача затрагивает все слои и цену ошибки имеет высокую — хороший кандидат
на то, чтобы агент готовил PR, а решение принималось руками.

## Задача для triage

Отдельно — задача, которую нужно завести **намеренно расплывчато**, чтобы проверить работу
режима triage на нечёткой постановке (шаг 3 проекта). Кандидат — задача 3: описать её так,
